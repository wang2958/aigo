> 生成：2026-10-09　|　适用：7 年 .NET 后端，AI 调用走 API（`qwen3.8-max` @ maas 中转）
> 定位：这不是一次性作业，是我**下次遇到就条件反射照做**的 SOP。放在天天看得到的地方。
> 详细模板见 `提示词模板库.md`；各实验数据见对应 W1/W2 笔记。

## 〇、三条贯穿全程的铁律（比任何单个流程都重要）

1. **判 AI 的输出，拿"需求"当尺子，不拿"现状代码"当尺子。**
   AI 若照着现有代码/现状推断，会把 bug 写成"正确"，绿灯给的是虚假安全感。标准答案来自我对业务的理解，不是来自模型。
2. **永远不信任模型输出的格式与事实——代码兜底。**
   prompt 只保证"尽量对"。要解析就 `enum`+`[JsonRequired]`+范围校验+失败重试；要事实就要出处、拿编译器验证。
3. **把问题问清楚 = 省钱 + 提质。**
   实测：含糊输入让推理模型思考 token 爆炸（857 vs 30），总成本差 9 倍。清晰的 prompt 是最高性价比的操作。

## 一、固化流程 A：用 AI 读陌生代码库（对应"读代码"最耗时项）

**触发**：接手新仓库 / 陌生模块，要快速建全局认知。
**心法**：靠结构信号建图，不逐文件通读。

- **第1步**：读解决方案/项目拓扑（`.sln` + 各 `.csproj`），画"谁引用谁"的分层依赖，标出空壳/废弃项目。
- **第2步**：找所有可执行入口（`Program.cs`/`Controller`/`*Worker`），判断每端职责。
- **第3步**：追一条关键路径——外部输入进来 → 落库/发消息出去，经过哪些层和类。
- **第4步**：路径上每个断言用 `grep`/文件内容**坐实**，不许靠命名猜。

**完成判据**：能画出分层依赖图 + 入口表(带文件:行号) + 一条关键路径流程。
**坑提醒**：先确认源码编码（本仓库是 GBK，UTF-8 读注释全乱码）。
→ 详见 `提示词模板库.md` 模板2、`W1任务4` 笔记。

## 二、固化流程 B：分步引导排查 bug（对应"排查 bug"最耗时项）

**触发**：线上工单、诡异结果、"为什么不对"类问题。
**心法**：不许 AI 跳到结论，强制它沿"这一次具体执行"的路径走，每步要证据。

- **第1步**：先让 AI 复述代码的分支结构，别猜。
- **第2步（核心闸门）**：拿**具体输入**逐行 trace，说走到哪行 return、返回什么，标真实行号。
- **第3步**：在出问题那行，列出关键变量的**实际值**（专治"看着该相等其实不等"：归一化/大小写/null/时区）。
- **第4步**：这时才归纳根因。
- **第5步**：最小修复 + 怎么验证（补哪条回归测试）。

**完成判据**：根因定位到具体行，且能给出验证方式。
**反直觉收获**：第2步"先 trace 别下结论"几乎决定成败；一句话提问省下的 token 会以"照错方向改代码"加倍还回来。
→ 详见 模板3、`W1任务4` 笔记（GetCountryName 归一化 bug 全过程）。

## 三、备用流程（用到时查模板库，暂不强制养成）

- **C. 生成边界单测**：给关键方法产边界用例，逐条判真伪（拿需求当尺子）。→ 模板1
- **D. 结构化输出**：要模型返回可解析 JSON = 精确 schema + 边界规则 + few-shot + **代码兜底**。→ 模板5
- **E. 代码审查**：贴 diff，让 AI 分「真问题/可改进/风格偏好」三档 + 标确定性，专治噪音与漏报。→ 模板4（待用真实 PR 跑通）

## 四、防幻觉反射（接到任何 API/事实先过这关）

- 红旗：**过度具体 + 零对冲**（敢给精确签名却不说"建议核对"）。
- 最危险的不是离谱的，是**完美踩中命名模式**的假 API（`Execute…Async` 成群时，AI 会凭空补一个）。
- 动作：**要版本号 + 官方文档链接 / 可运行验证**；.NET 里最快的裁判是**把代码真编译**（假方法名直接 `CS0117/CS1061`）。
→ 详见 `W2任务5-幻觉识别实测.md`。

## 五、模型与成本策略

- **按任务难度分层配模型**：默认便宜快档（`qwen3.8-flash` / `deepseek-v4-flash` 级）；多步推理/架构/难 debug 才升 `qwen3.8-max` 级。实测简单题上贵模型质量无优势却慢 3 倍、多烧 711 思考 token。
- **比"每任务成本"不是"每 token 单价"**：同 prompt 不同厂商 token 数不同（qwen 98 vs deepseek 39）。
- **盯 `usage` 的 `reasoning_tokens`**：推理模型的隐形成本大头。简单任务查端点是否支持 `enable_thinking:false`/`thinking_budget` 关掉。
→ 详见 `W2任务3-token计费实测.md`、`W2任务4-模型选型实测.md`。
