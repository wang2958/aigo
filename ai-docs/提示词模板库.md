# 提示词模板库

> W1 任务 6 的产出。目标 ≥5 个自己会反复用的模板。
> 每个模板都是「五手法」的落地：①角色 ②上下文 ③输出格式 ④few-shot ⑤先复述。
> 用法：复制模板 → 把 `{{占位符}}` 换成你的真实内容 → 发给模型。

---

## 模板 1 · 给真实方法生成边界单测

**适用场景：** 手头一个有分支/边界逻辑的方法（金额计算、状态判断、日期处理、权限校验等），要让 AI 产出能覆盖真实边界的单测，而不是一堆 happy path。

**关键：** `{{已知的真实 bug 或易错点}}` 是整条提示词最值钱的部分——它把你的领域知识注入模型，是它自己永远猜不到的。别省略。

```
【①角色】你是资深 .NET 后端，精通 {{测试框架，如 xUnit}} 和边界值分析。

【②上下文】这是被测方法：
{{贴完整方法源码}}

业务规则：{{用一两句话说清计算/判断顺序、约束条件}}
{{已知的真实 bug 或易错点：我们线上出过 ___，因为 ___}}

【⑤先复述】动手前，先用一句话复述你理解的核心逻辑和关键约束，
确认无误再写。（如果我理解错了顺序/边界，你现在就拦住我）

【④few-shot】照这个风格产出（范本）：
{{贴一个你满意的测试方法，锁定命名风格/框架/断言方式}}

【③输出格式】先用表格列出你打算覆盖的用例：
| 测试方法名 | 输入 | 期望输出 | 覆盖的边界 |
表格确认覆盖全了，再给完整代码，同类用例用 [Theory]+[InlineData] 合并。
重点覆盖：{{列出你最担心的几个边界，如 临界值/空集合/null/负数/溢出}}
```

**验收标准（怎么判断模型输出合格）：**
- 表格里是否出现了你 `{{重点覆盖}}` 里点名的每一个边界？漏了就是没读懂上下文。
- 是否为那个"线上 bug"专门造了回归测试？没有就是把②当耳旁风。
- 期望值自己手算一遍——模型算错边界值很常见（尤其涉及顺序、四舍五入、临界 `>=` vs `>`）。
- 逐条问自己：这个测试**真能抓到 bug**，还是只是"看着在测"？

**首次实战记录：** 2026-10-08 用 `CalcOrderDiscount`（满减+会员折+券叠加）跑通，模型正确产出了 `=1000` 临界、券>总额钳位到 0（回归线上 bug）、Items 为空等边界。
